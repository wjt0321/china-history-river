# 设计说明 — china-history-river

> 本文档解释项目的视觉隐喻、交互策略、数据边界与工程取舍，用于作品集展示和后续迭代参考。

---

## 1. 设计目标

本项目不是单纯的历史资料列表，也不是传统地图册复刻，而是一件面向作品集展示的交互式数据可视化作品。

核心目标：

1. **让历史时间可感知**：用“河流”隐喻表达朝代更替、延续、分裂与汇合。
2. **让空间变化可观察**：用动态疆域地图展示不同朝代控制范围的扩张、收缩与重心变化。
3. **让内容层级可探索**：用卷轴式详情面板承载帝王、大事、文化、经济与疆域演变。
4. **让视觉风格有记忆点**：以“数字博物馆 / 古画卷轴”为统一风格，而不是纯科技或纯古风。

---

## 2. 为什么使用“河流”作为时间隐喻

中国历史的朝代更替并不是简单的线性进度条。它包含：

- 长短不一的统治周期；
- 分裂与统一的交替；
- 制度、文化和族群的连续性；
- 疆域重心在东西南北之间的变化。

因此项目没有采用常见的直线时间轴，而是使用 **河流式 Canvas 时间轴**：

- 河段长度对应朝代时间跨度；
- 弯曲与渐变制造“历史流动”的感觉；
- 当前朝代通过脉冲和颜色强调；
- brush 缩放让用户可以从五千年尺度进入局部时代。

这种设计让时间不是静态刻度，而是一条可以探索的历史长河。

---

## 3. 为什么采用“数字博物馆 / 古画卷轴”风格

项目需要同时满足两个方向：

- **历史厚重感**：不能像普通数据看板一样冷冰冰。
- **现代技术感**：需要体现前端、地图、Canvas 和动画能力。

因此采用“数字博物馆”作为主视觉方向：

- 背景使用深空黑与暗色地形底图，类似展厅环境；
- 朝代色使用降饱和文物色，避免高饱和荧光；
- 详情面板采用卷轴隐喻，承接古籍阅读体验；
- 都城标记使用朱印形式，与中国传统印章关联；
- 粒子系统只做氛围，不抢占地图和内容主体。

这个方向比纯水墨更适合 WebGL / Canvas 的现代交互，也比纯科技风更有人文温度。

---

## 4. 地图策略与 MapLibre 选择

### 4.1 为什么选择 MapLibre

项目选择 MapLibre GL 而非 Mapbox，主要原因：

- 开源，无需 Mapbox Token；
- 支持 GeoJSON 动态图层；
- 能与 Vite / React 稳定集成；
- 适合用多层 line/fill 制作疆域发光、墨晕和边界效果；
- 可部署到 GitHub Pages，无额外服务依赖。

### 4.2 地图视觉原则

地图不是主角本身，而是历史叙事的空间底座。因此：

- 底图使用 `CartoDB dark_nolabels`，减少现代地名干扰；
- 栅格底图降低 opacity 和 saturation；
- 当前朝代疆域使用主题色填充与边线光晕；
- 都城使用朱印标记而非现代地图 pin；
- 事件点使用圆点和 popup，保持克制。

---

## 5. 疆域数据边界

### 5.1 简化原则

项目中的 `public/dynasties/*.json` 为简化 GeoJSON，用于表达朝代疆域变化趋势，而不是精确历史地图。

简化目标：

- 保持朝代空间范围的大致方向；
- 避免过多顶点影响性能和视觉清晰度；
- 用统一风格表达 14 个朝代的宏观变化；
- 服务交互叙事，而不是替代专业历史地图。

### 5.2 免责声明

> 本图为历史疆域简化示意，用于展示动态变化趋势，不代表精确边界或现代行政、主权范围。

后续如果继续增强可信度，应在每个朝代增加更细来源说明，并区分“文献记载 / 考古证据 / 传统说法 / 学界争议”。

---

## 6. 内容结构取舍

每个朝代采用统一的 `Dynasty` 数据模型，覆盖：

- 基础信息；
- 一句话定位；
- 简介；
- 兴亡原因；
- 帝王长廊；
- 大事年表；
- 经济数据；
- 关键战役；
- 文化遗产；
- 对外关系；
- 疆域演变；
- 史家评价。

这样做的好处是：

- 详情面板可以统一渲染；
- 朝代之间有可比较结构；
- 后续可以扩展搜索、筛选、叙事模式；
- 数据完整性可以用测试保护。

缺点是：

- 早期朝代史料稀疏，部分维度天然不均衡；
- 历史评价与现代叙述容易混杂；
- 后续需要更细的来源标注与争议标签。

---

## 7. Canvas 与 React 的取舍

时间轴与粒子系统使用 Canvas，而不是 SVG 或 DOM。

原因：

- 粒子系统需要每帧更新，Canvas 更适合大量轻量对象；
- 河流时间轴需要自由曲线、渐变和脉冲效果；
- 避免大量 DOM 节点导致布局和样式复杂度上升。

同时，为避免 Canvas 动画导致 React 重渲染：

- `Timeline` 和 `AtmosphereParticles` 主要通过 `useRef` 操作 Canvas；
- 高频状态读取使用 `useAppStore.getState()`；
- React 只负责组件生命周期和容器挂载。

后续可优化方向：

- `Timeline` 拆分绘制函数；
- 使用 dirty flag 降低不必要重绘；
- 将 mouse 事件升级为 Pointer Events，兼容触摸设备。

---

## 8. 性能取舍

当前最大的性能来源是 MapLibre GL。项目已经采取：

- `manualChunks` 将 `maplibre-gl` 和 `framer-motion` 拆包；
- `MapView` 懒加载，在开场动画完成后再挂载；
- `DetailPanel` 首次打开时懒加载；
- 生产 sourcemap 按环境控制；
- 图片优化脚本预留。

仍需接受的现实：

- `maplibre-gl` chunk 本身较大；
- 地图组件一旦加载，WebGL 初始化仍有成本；
- Canvas 动画在低端设备上可能需要降帧。

后续应通过移动端适配、Lighthouse 检查和视觉回归继续优化。

---

## 9. 可访问性取舍

项目目前偏视觉作品，已经考虑：

- `prefers-reduced-motion` 下跳过部分动画；
- 自定义光标在触屏设备禁用；
- 关键内容仍以文本形式存在于详情面板。

后续需要补强：

- 详情 tab 的 `role="tablist"` / `role="tab"` / `aria-selected`；
- 顶部朝代下拉的 `aria-expanded` / `aria-controls`；
- `Esc` 关闭详情面板；
- Canvas 时间轴的键盘替代导航；
- 移动端 bottom sheet 交互。

---

## 10. 后续叙事方向

当前项目是“探索型可视化”。下一阶段可以升级为“叙事型可视化”：

- 增加“开始巡游”按钮；
- 按朝代顺序自动切换；
- 配合地图飞行、事件高亮、旁白文本；
- 用户可暂停、跳过、回到自由探索模式。

推荐叙事结构：

1. 夏商周：文明源流与礼制形成；
2. 秦汉：大一统框架建立；
3. 三国两晋南北朝：分裂、迁徙与融合；
4. 隋唐：制度整合与开放盛世；
5. 宋元明清：经济、技术、疆域与近世转折。

这会让项目从“功能完整”进一步走向“作品完整”。
